iPhone UI audit

I captured every iPhone tab, the three detail screens, every More hub and the screens under them on iOS 26.4 and iOS 27.0, then went through them for alignment problems and inconsistencies between screens. Three problems are worth fixing soon. The rest are smaller inconsistencies that add up.

iPhone 17 Pro simulator iOS 26.4 + iOS 27.0 Seeded fixture services Branch iphone-duo-polish

Fixed this session

These are already on iphone-duo-polish.

Gap above "Recently Searched"

The recent-searches list had its own 44pt empty top inset, on top of the inset that already holds the Discover/Library bar, which left a wide empty band. I removed the extra inset in SearchView.swift.

Bottom search field on iOS 27

On iOS 27 the Search tab used the new .prominent role. That role only changes how the tab looks, so the field stayed at the top of the screen. The tab is .search again on every iOS version. On iOS 27 the tab view also uses .tabViewSearchActivation(.searchTabSelection), which brings back the bottom field. On iOS 27 the keyboard now opens as soon as you tap Search; iOS 26 is unchanged.

Findings

P1 means visibly broken, P2 means inconsistent enough that users will notice, and P3 is polish. Each finding names the code it comes from and a suggested fix. None of these are fixed yet.

P1

Detail search buttons break words mid-way

On Series and Movie detail, the Automatic and Interactive buttons wrap their titles with a hyphen ("Automat-ic", "Interac-tive") and cut their subtitles to "Search all…". Each button is about 175pt wide. After the leading icon, two 12pt gaps, the trailing arrow and the padding, the title has about 75pt, which "Automatic" only just fits.

SonarrSeriesDetailView.swift:1005 · RadarrMovieDetailView.swift:1086 (two copies of the same label)

Fix: share one label view. Give the title .lineLimit(1) and .minimumScaleFactor(0.85), cut the spacing to 8, and drop the trailing arrow on compact width, or stack the two buttons vertically on iPhone.

P1

Empty and error states are not vertically centred, and differ from screen to screen

Some states sit in the top third of the screen and others in the middle. ServiceErrorView and scrollableUnavailableState() both give the state a fixed minHeight: 360 slot at the top of a list or scroll view, and Health places its ContentUnavailableView as a list row. Search's "No Results" is a bare ContentUnavailableView, so it centres in the whole screen. The result: Search idle, Missing, Requests and Health all show their icons at different heights, and none of them line up with "No Results".

ServiceErrorView.swift:39 · View+ScrollableUnavailableState.swift:16 · ArrHealthView.swift:279

Fix: give both containers the scroll view's height instead of 360 (for example .containerRelativeFrame(.vertical) inside the ScrollView), and in lists show the state as an .overlay on the empty List rather than as a row.

P1

Jellyfin Libraries is filed in a different place on iPhone and iPad

The iPad sidebar puts Libraries under Media Server. On iPhone, the Media Server hub lists only Sessions, Transcoding and Plugins, and Jellyfin Libraries appears under Library Management instead. Media Server's own "not set up" message still promises "sessions, libraries, transcoding, and plugins". The capture walk, which follows the iPad filing, couldn't find it on either iOS version.

RootTab.swift:35 (sidebar) · MoreView.swift:1960 (category "Library Management") · MoreView.swift:3946 (hub rows)

Fix: choose one home. Media Server matches the sidebar and the empty-state text, so add a Libraries row to the compact Media Server hub, or move it in both places.

P2

Some navigation titles are left-aligned, most are centred

Pushed screens centre their title, except Missing and Backups. iOS moves an inline title to the leading edge when the trailing toolbar items are too wide. On Missing that's the text button "Search All Missing", and on Backups it's three separate icon buttons.

ArrWantedView.swift:313-318 · ArrBackupsView.swift:386

Fix: make "Search All Missing" an icon button with that accessibility label, and put Backups' three actions in one Menu, which matches Users and Indexers.

P2

Segment bars use mixed alignment, even on the same screen

Thirty of the 32 TrawlSegmentBars are leading-aligned. Search's Discover/Library scope bar and Calendar's scope bar are centred. Search shows both kinds: the centred scope bar while you type, then a leading All/Series/Movies bar once results appear, so the buttons jump sideways when the first result lands.

SearchView.swift:125 · ArrCalendarView.swift:679 · default in TrawlSegmentBar.swift:8

Fix: make both Search bars leading, or both centred. Leading matches the rest of the app.

P2

Root tab titles have two different styles

Downloads, Series and Movies use a compact inline-large title with a count under it ("2 items", "12 series"). More and Search use the full large title with no count. Moving between tabs, the title changes size and position.

Fix: pick one title style for all five tabs. If the counts matter, give More and Search a quiet subtitle too.

P2

Counts appear in four different places

Downloads, Series and Movies put their count in the navigation subtitle. Users puts it in a section header ("2 users"), Issues in a footer ("1 issue"), and Setup Check in the row subtitle on the System hub ("6 problems found").

Fix: use the navigation subtitle wherever a screen has one list, which Issues and Updates already use for their service name.

P2

Setup Check behaves like a sheet inside a push stack

Every other row on the System hub pushes a screen with a back button. Setup Check opens with "Done" and "Next" and covers the tab bar, so back gestures and the tab bar don't work on it. On iOS 27 it also stopped the capture walk until "Done" was tapped.

MoreView.swift:684

Fix: make it a pushed screen from System and save the sheet for the first-run flow, or present it explicitly as a sheet everywhere.

P3

Smaller inconsistencies

  • Refresh controls. Updates and Users have a refresh button in the toolbar, while every other list relies on pull to refresh.
  • Row icons. Hub rows use tinted rounded tiles. Settings' service list, Root Folders and Disk Space use bare glyphs, and Download Clients uses its own arrow chain.
  • Search button in segment bars. Downloads, Series, Movies, Requests and Issues start their segment bar with a search button. Health, Missing, Updates and Backups have no search at all, even with long lists.
  • Raw error text. Missing's error shows the decoder's own message ("The data couldn't be read because it isn't in the correct format"), once per service. It comes from a fixture gap here, but real servers can return the same thing.
  • Detail page styles. Series and Movie detail use a full-bleed tinted page with a poster. Download detail uses the plain grouped style with an icon tile. That's defensible, but they read as different apps.

iOS 26.4 vs iOS 27.0

Apart from the search tab, which is fixed, the two versions render almost identically. The differences are system styling: iOS 27 draws the More search field and the detail-page glass buttons flatter and greyer. The notification accessory shows different text on each because the two simulators had different notification history. The one behaviour difference is intended: on iOS 27 tapping Search goes straight into active search with the keyboard up, so it has no idle Search screen to capture. Every pair below comes from the same walk.

How these were made

The screenshots come from the new opt-in testCaptureIPhoneSurfaces in TrawlUITests/IPadSurfaceCaptureUITests.swift, which seeds every service from the existing fixture servers. To rerun it:

TEST_RUNNER_TRAWL_IPHONE_CAPTURE=1 TEST_RUNNER_TRAWL_SCREENSHOT_EXPORT_DIR=/tmp/shots xcodebuild test -project Trawl.xcodeproj -scheme Trawl -destination 'platform=iOS Simulator,id=<sim>' -default-test-execution-time-allowance 1800 -only-testing:TrawlUITests/IPadSurfaceCaptureUITests/testCaptureIPhoneSurfaces

TMDb is deliberately unreachable in fixtures, so posters are placeholders and Search's idle screen shows "Couldn't Load Trending". The Missing error is a fixture gap, not an app bug.
