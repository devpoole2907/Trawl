Import issues, fixed by cause

Today a stuck import is one row per download. You open each one, read Sonarr’s or Radarr’s message, work out what it means, and pick an action. Most of those messages fall into five causes, and each cause has one fix. This page lays out four ways to use that.

Why it feels like a chore

  • The diagnosis is buried. The reason lives in a status message inside the row’s detail, written in Sonarr’s words.
  • The same fix is repeated. Three downloads failing for one wrong path mapping look like three separate problems.
  • The order is wrong. Rows are sorted by download, not by how much one tap would clear. A path problem that causes half the list sits next to one bad release.
  • Nothing says what to do. The actions offered (Remove, Blocklist, Manual Import) are the same for every row, whether or not they fit.

The five causes

Every option below starts from the same step: read each queue item’s status messages and put it in one bucket. Unknown messages fall into “Something else”, which keeps today’s per-row view.

Recommended

A · Grouped by cause

Issues becomes a short list of causes instead of a long list of downloads. Each group says what happened in plain words, how many downloads it covers, and offers the one fix as a single button. “Show 3” opens the items, where you can untick one before applying. Groups are ordered by how much one tap clears, so a path problem comes first.

Good

  • Biggest change in effort for the least new UI: it’s still the Issues filter.
  • Bulk where bulk is safe, per item where it isn’t.
  • Works the same on iPhone, iPad and Mac.

Watch out

  • A wrong bucket hides a real problem under a confident label. “Something else” has to stay visible.
  • Batch actions need the same undo window as Approve and Decline.

B · One at a time

A focused flow, like clearing an inbox. Each card shows one download, Sonarr’s message, a one-line plain explanation and the recommended action as the main button, with Skip beside it. Similar items are batched behind the card (“3 × path not found”).

Good

  • Very low effort per decision: read, tap, next.
  • Good for the “Can’t match” cases, which need attention anyway.

Watch out

  • Still one tap per download, so ten “already have it” items are ten taps.
  • A mode you enter and leave, rather than a view you glance at.

C · Fix plan

Trawl reads everything and proposes a plan: a checklist of fixes, each covering one or more downloads, all ticked except the ones that need you. One “Apply” runs them in order, path fixes first, then retries, removals and searches.

Good

  • Fewest taps of any option: often one.
  • Order is handled for you, so the path fix happens before the retries that depend on it.

Watch out

  • Applying many changes at once needs a clear summary afterwards and a way to see what was done.
  • Trusting a plan you didn’t read is how files get deleted by mistake.

D · Handle it automatically

A small settings screen: per cause, choose “handle automatically” or “always ask me”. Safe causes are handled as they appear and logged in Alerts; only what needs a person reaches Issues. Cleanuparr does this server-side already, so if it’s connected, Trawl would point at it instead.

Good

  • The best answer for the boring causes: you never see them.
  • Fits the Alerts log we just built.

Watch out

  • Only runs while Trawl is running, unless it’s a server-side job. On a phone that’s rarely.
  • Duplicates Cleanuparr for anyone who has it.

Recommendation

Build A now, with C’s ordering, and add D later as opt-in rules. A is the everyday view and makes the common case a couple of taps. Ordering groups by how much they clear, path first, borrows the best idea from C without a separate “apply everything” step. B’s card fits “Can’t match” items, so the Choose Title button can open that focused flow. D waits until A has shown which causes are common enough to automate.

Open questions

Where does it open from?

The bar’s “3 failing” currently opens Downloads on the Issues filter. With A it would open the grouped view directly. On iPad and Mac it would be the Downloads row’s Issues filter.

Undo for batch actions

Remove and Blocklist are destructive. The same four-second Undo as Approve and Decline, held by the manager, seems right.

Path fixes across servers

With two Sonarrs, a path group may belong to one of them. The group should say which and open that server’s mappings.

Retry after fixing

After a path mapping change, should Trawl retry the imports for you, or leave a “Retry 3” button?
